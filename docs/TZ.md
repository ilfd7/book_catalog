# Техническое задание
## на разработку веб-приложения «Каталог домашней библиотеки»

## 1. Общие сведения

Программа «Каталог домашней библиотеки» — веб-приложение на языке Python (фреймворк Flask) с реляционной базой данных SQLite, предназначенное для учёта книг домашней библиотеки.

## 2. Назначение и цели

Приложение позволяет пользователю:
- вести учёт книг (название, автор, жанр, год издания, описание);
- искать книги по названию и автору;
- фильтровать книги по жанрам;
- создавать резервные копии базы данных.

## 3. Функциональные требования

- **FR-1**: Отображение списка всех книг на главной странице.
- **FR-2**: Просмотр подробной информации о книге.
- **FR-3**: Добавление новой книги через веб-форму.
- **FR-4**: Редактирование существующей книги.
- **FR-5**: Удаление книги из каталога.
- **FR-6**: Поиск книг по названию и автору.
- **FR-7**: Фильтрация списка по жанру.
- **FR-8**: Валидация обязательных полей формы (название, автор, жанр, год).
- **FR-9**: Проверка корректности года издания (число).
- **FR-10**: Создание резервной копии базы данных.
- **FR-11**: Просмотр списка резервных копий.
- **FR-12**: Восстановление базы данных из резервной копии.

## 4. Нефункциональные требования

- **NFR-1**: Приложение написано на Python 3.9+ с использованием Flask.
- **NFR-2**: База данных — SQLite, доступ через SQLAlchemy ORM.
- **NFR-3**: Корректные HTTP-коды ответов (200, 302, 404, 500).
- **NFR-4**: Контроль целостности резервных копий через SHA-256.
- **NFR-5**: Атомарная запись архивов резервных копий.
- **NFR-6**: Защита от path traversal при восстановлении.

## 5. Интерфейс

Веб-интерфейс состоит из страниц:
- Главная — список книг с поиском и фильтрацией;
- Добавление книги — форма с валидацией;
- Просмотр книги — полная информация и действия;
- Редактирование книги — форма с предзаполненными полями.

## 6. Алгоритм резервного копирования

1. Вычислить SHA-256 хеш файла базы данных.
2. Сформировать манифест `{имя_файла: хеш}`.
3. Упаковать БД и манифест в ZIP-архив во временный файл.
4. Атомарно переименовать временный файл в целевое имя `backup_<дата_время>.zip`.

## 7. Формат данных

База данных SQLite содержит таблицу `book` с полями:
- `id` — INTEGER PRIMARY KEY;
- `title` — VARCHAR(200), обязательное;
- `author` — VARCHAR(100), обязательное;
- `genre` — VARCHAR(50), обязательное;
- `year` — INTEGER, обязательное;
- `description` — TEXT, необязательное.

## 8. Требования к надёжности

- Среднее время наработки на отказ — не менее 72 часов непрерывной работы.
- Время восстановления работоспособности после сбоя — не более 15 минут (за счёт механизма резервного копирования и восстановления).
- Сохранность данных обеспечивается ежедневным резервным копированием с контролем целостности через SHA-256.

## 9. Требования к безопасности

- Валидация всех пользовательских вводов на стороне сервера.
- Защита от SQL-инъекций через использование ORM SQLAlchemy.
- Защита от path traversal при восстановлении из резервных копий.
- Хранение паролей и секретных ключей в переменных окружения, а не в коде.

## 10. Порядок контроля и приёмки

- Функциональные требования (FR-1…FR-12) проверяются по 30 ручным тест-кейсам.
- Ключевые модули покрыты 21 автоматическим тестом (unittest).
- Нефункциональные требования (NFR-1…NFR-6) проверяются анализом кода и результатами профилирования.
- Критерий приёмки: все тесты имеют статус Passed, приложение развёрнуто и доступно по адресу http://127.0.0.1:5000.
